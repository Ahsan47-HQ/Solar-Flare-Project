# Phase 4: verified evaluation and interpretation

Run `.\.sfd\Scripts\python.exe -u rebuild_evaluate.py` from the repository root after Phase 2 and 3 training. This independently checks saved models against current Phase 1 input hashes, held-out IDs, recomputed metrics, and reload predictions. It verified all 33 completed runs, with zero rejected. `publish_rebuild_reports.py` then refreshes the main report paths.

The [full verified summary](reports/rebuild/phase4/verified_summary.md) and [machine-readable results](reports/rebuild/phase4/verified_results.json) are authoritative. The main [Phase 4 results CSV](reports/phase4/phase4_results.csv) and [summary](reports/phase4/phase4_summary.md) mirror them. AP and TSS by lead are plotted in `reports/rebuild/phase3/`; feature importance and 12-hour observation-window patterns are plotted in `reports/rebuild/phase4/`.

The temporal-feature comparison uses matched held-out rows and 500 paired bootstrap replicates resampling active regions, so repeated overlapping windows stay together. Every reported 95% AP-difference interval includes zero. The interpretation sample uses one window per region; at 24 hours in the chronological test cohort, positive windows come from only 20 distinct active regions. TreeSHAP and pre-flare patterns are associations, not causal explanations.

Targets use the MFLARE/XFLARE **peak** annotation. H hours means a peak within the 24-hour interval starting H hours after the issue time. Thus results measure lead to peak rather than lead to onset. Full coverage requirements censor windows near the end of a series, especially at 48 hours. The test set was used for final evaluation, while thresholds and XGBoost iteration count came from validation. See [REBUILD.md](REBUILD.md) for the complete method and limitations.
